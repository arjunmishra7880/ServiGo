1. 30-Second Elevator Pitch & Project Overview

🎤 What to say when the examiner asks: "Introduce your project / Apne project ke bare mein batao" "Good morning/afternoon Sir/Ma'am. My project is ServiGo (Local Service Finder). It is a full-stack hyper-local on-demand marketplace connecting local residents with verified service professionals such as electricians, plumbers, appliance technicians, and carpenters. We built this application using React 19 + Vite on the client side, Node.js + Express on the backend, Prisma ORM with SQLite as our database layer, and Socket.io for real-time bi-directional chat and notification alerts. It features complete Role-Based Access Control (Customer, Service Provider, Admin), interactive Leaflet map discovery, and an intelligent automated customer support assistant."

Problem Statement vs. ServiGo Solution

Offline / Conventional Market Problem ServiGo Digital Solution

3. Database Design & Entity Relationships (ER)

The relational database is orchestrated using Prisma schema definitions in server/prisma/schema.prisma:

User Account
Stores authentication details, role (customer, provider, admin), and contact information.
1 : 1
Provider Profile
Stores business name, bio, experience, hourly rate, city, and isVerified admin badge status.
1 : N
Service Catalog
Individual offerings with price, category link, title, and description available for booking.
Model Key Attributes Relationships & Constraints
User id, email, password, name, phone, role Primary identity. 1-to-1 with ProviderProfile; 1-to-Many with Bookings (as customer), Reviews, and Conversations.
ProviderProfile id, userId, businessName, bio, hourlyRate, isVerified, city 1-to-1 foreign key to User (onDelete: Cascade). 1-to-Many with Services, Reviews, and Conversations.
Category id, name, description, icon 1-to-Many with Services. Holds 8 seeded categories (IT, Appliances, Plumbing, Electrician, Cleaning, Carpentry, Painting, Pest Control).
Service id, providerId, categoryId, title, description, price Links a Provider to a Category with custom pricing. 1-to-Many with Bookings.
Booking id, customerId, serviceId, bookingDate, address, status, totalAmount Core transaction entity. References customer (User) and Service. Status: pending, accepted, completed, cancelled.
Review id, customerId, providerId, rating (1-5), comment, createdAt Stores verified customer feedback linked directly to Provider's profile for aggregated rating computation.
Conversation / Message id, customerId, providerId, lastMessage | id, conversationId, senderId, content Persists 1-on-1 socket conversations. Unique composite constraint: @@unique([customerId, providerId]).

5. Security, Authorization & Authentication Architecture

🔒 How Authentication Works (Examiner Question)
  1. Password Hashing: Passwords are never saved in plaintext. During registration, bcryptjs.hash(password, 10) applies 10 salt rounds to generate an irreversible digest.
  2. JWT Issuance: Upon successful credentials verification in /api/auth/login, the server signs a JSON Web Token with payload { id, email, role } using an environment secret key.
  3. Token Transmission: The client stores the JWT in localStorage and injects it into the HTTP header: Authorization: Bearer <token>.
  4. Middleware Verification: authenticateToken intercepts incoming protected requests, decodes the token with jwt.verify(), and attaches req.user.
  5. Role-Based Authorization (RBAC): authorizeRoles('admin') or authorizeRoles('provider') protects restricted endpoints from unauthorized user roles.

6. Top 15 Viva Voce Questions & High-Scoring Answers

Q1 Explain the overall architecture of your system.
"Our application follows a decoupled 3-Tier Model-View-Controller (MVC) Client-Server Architecture. The presentation layer is built as a Single Page Application using React 19 and Vite. The application logic is governed by an asynchronous Node.js Express REST API server alongside a Socket.io WebSocket server for real-time events. The data tier utilizes Prisma ORM with SQLite (readily switchable to PostgreSQL/MySQL in production)."
Q2 Why did you choose React + Vite over traditional server-rendered templates or CRA?
"Create-React-App (CRA) is deprecated and relies on Webpack, which causes slow development server starts and heavy build overhead. Vite uses native ES modules (ESM) in development with Hot Module Replacement (HMR) that is virtually instantaneous. Furthermore, React's component-based virtual DOM ensures high UI responsiveness without full page reloads."
Q3 How does JWT authentication differ from traditional session-cookie authentication?
"Traditional session-based authentication requires the server to store active session IDs in server memory or a Redis store, which causes scalability bottlenecks in distributed server setups. JWT is stateless—the token itself securely encapsulates user identity and permissions in a cryptographically signed payload. The server only needs to verify the cryptographic signature without querying session tables on every request."
Q4 What is an ORM, and why did you choose Prisma over raw SQL queries?
"An Object-Relational Mapper (ORM) bridges object-oriented programming code with relational database tables. We chose Prisma because it provides compile-time type safety, automated database migrations, clean schema definition syntax, and complete immunity against SQL injection attacks through automatic parameterized queries."
Q5 How does real-time communication work with Socket.io? Compare it with HTTP.
"HTTP is a stateless, half-duplex protocol where the client must initiate requests and the server cannot push data proactively. Socket.io establishes a full-duplex, persistent TCP connection via WebSockets. We utilize Socket rooms (e.g. conversation:12) so when a customer or provider emits a message, only members of that room receive it instantly without polling the database repeatedly."

6. Top 15 Viva Voce Questions & High-Scoring Answers (Contd.)

Q6 What are the lifecycle states of a service booking in your application?
"A booking operates as a state machine: 1. pending: Created by customer, waiting for provider response. 2. accepted: Provider confirms the appointment date and time. 3. completed: Service is fulfilled; enables customer review submission. 4. cancelled: Terminated by either customer or provider prior to fulfillment."
Q7 Why do you hash passwords using bcryptjs instead of MD5 or SHA-256?
"Standard algorithms like MD5 or SHA-256 are general-purpose cryptographic hash functions designed to be fast, making them highly vulnerable to GPU-accelerated brute-force attacks and precomputed Rainbow Table lookups. bcrypt is a key-derivation function that incorporates a salt (to defeat rainbow tables) and is computationally slow with configurable work factors (salt rounds = 10) to withstand brute-force attacks."
Q8 What is CORS, and why did you configure it on the Express server?
"Cross-Origin Resource Sharing (CORS) is a browser security policy that prohibits a web application running on one origin (e.g., http://localhost:5173) from accessing resources on a different origin (e.g., http://localhost:5000). We installed and configured the cors() middleware in Express to explicitly allow authorized frontend clients to execute API requests."
Q9 How do you manage global state across the React frontend?
"We utilized React's Context API (AuthContext and ThemeContext). AuthContext maintains user session information (logged-in user profile, JWT token, login/logout handlers) and persists them in localStorage, avoiding the complexity and boilerplate of Redux while providing accessible state across all components."
Q10 How does your rule-based support chatbot work?
"The SupportChatBot component implements an offline natural language knowledge base (KB). User input text is normalized and evaluated against keyword pattern arrays using regex and token matching (e.g. matching 'book', 'hire', 'schedule'). If a match occurs, the appropriate formatted guidance is rendered instantly; otherwise, it offers suggested question chips."

6. Top 15 Viva Voce Questions & High-Scoring Answers (Contd.)

Q11 How did you implement map-based provider discovery without paid APIs?
"Instead of using Google Maps API, which requires paid billing accounts and API keys, we used Leaflet.js with OpenStreetMap (OSM) tiles. We plot provider coordinates dynamically on an interactive map layer with custom markers and popup action buttons."
Q12 What happens if a user tries to access a protected route without a token?
"Our authenticateToken middleware checks the Authorization request header. If missing, it immediately halts execution and returns HTTP 401 Unauthorized. If the token is tampered with or expired, jwt.verify() throws an exception and returns HTTP 403 Forbidden."
Q13 Explain the difference between Cascade delete in your Prisma schema.
"We declared onDelete: Cascade on child relationships (such as User to ProviderProfile, or ProviderProfile to Services). If a user account or provider is deleted from the system, all associated services, bookings, messages, and reviews are automatically removed by the database to prevent orphaned records and maintain referential integrity."
Q14 How can this system scale to handle thousands of concurrent users?
"To scale ServiGo for production: 1. Migrate SQLite to a managed cluster such as PostgreSQL or MySQL. 2. Deploy the Express backend in containers (Docker) behind an NGINX reverse proxy or AWS ALB. 3. Use Redis Pub/Sub with Socket.io Redis Adapter to distribute WebSocket events across multiple server instances. 4. Place static assets and client build files on a global CDN (Cloudflare/Vercel)."
Q15 What are the current limitations and future scope of ServiGo?
"Current Limitations: Direct cash-on-delivery/offline payments; lack of SMS OTP verification. Future Scope: Integration of payment gateways (Razorpay / Stripe), live GPS technician tracking on maps during transit, AI-powered price recommendation algorithms, and native mobile apps using React Native."
